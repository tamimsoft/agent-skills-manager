# Phase 0 Verification Plan
## Global Agent Skill Manager — Experiments V0–V22

**Companion to:** `global-agent-skill-manager-guideline-v4.md`
**Status:** `AWAITING_APPROVAL`
**Scope:** This document is the method for Phase 0 only. It does not implement anything. No real project, real agent configuration, or real skill library file is modified by any experiment below — see §1.

---

# 1. Ground Rules (apply to every experiment)

1. **Read-only against reality.** Every experiment that needs to observe agent *behavior* (not just version/help text) runs against a **sandboxed copy**, never the real `~/.agents/skills/`, `~/.junie/`, `~/.config/opencode/`, `~/.kilo/`, `~/.config/kilo/`, or Digital Pharmacy itself.
2. **Sandbox, not mock.** The real `kilo`, `junie`, and `opencode` binaries are used, pointed at a scratch environment — not reimplementations of them. A mocked agent would only prove the manager's assumptions about itself, not the agent's real behavior.
3. **Redact before writing.** Any tracked document (the Phase 0 review) redacts absolute home paths, usernames, and config values, per the guideline's §4.5-equivalent rule.
4. **One experiment, one verdict.** Each experiment ends in exactly one of: **Confirmed** (behavior matches the design's assumption), **Contradicted** (behavior differs — stop and revise before Phase 1 depends on it), or **Inconclusive** (could not be observed safely or at all — document as a known limitation, do not guess).
5. **No experiment blocks on another unnecessarily.** Where V-items are independent, run them in any order; where one depends on another's sandbox setup, that dependency is noted in its row.

---

# 2. Sandbox Setup (shared infrastructure)

Before V1 or any behavior experiment, build the shared sandbox:

1. Create a scratch root, e.g. `/tmp/agent-skills-phase0/`.
2. Inside it, create a fake `$HOME` layout: `home/.agents/skills/`, `home/.junie/`, `home/.config/opencode/`, `home/.config/kilo/`, `home/.kilo/skills/`, `home/.claude/skills/`.
3. Populate `home/.agents/skills/` with a handful of **representative sample skills**, copied (not symlinked) from the real library so originals are never touched:
   - One ordinary skill with valid frontmatter (`name`, `description`).
   - One skill with **no frontmatter** (a stand-in for `flutter-tamim`/`hive-db-tamim` — same structure: nested folder, a script, a file with a space in its name).
   - Two skills with the **same `declared_name`** in different directories (for collision experiments).
   - One skill with **malformed** frontmatter (unterminated quote, bad indentation).
4. Create a scratch project directory, e.g. `/tmp/agent-skills-phase0/project/`, with a minimal `pubspec.yaml` (Flutter marker) so detection-adjacent experiments have something realistic to point at, without using Digital Pharmacy itself.
5. **V0 — Sandbox capability check (prerequisite for V1–V22):**
   - **Question:** Can each agent be pointed at the scratch `$HOME` (via the `HOME` environment variable, an explicit config-path flag, or an environment variable the agent documents) without touching the real configuration, and does it still run normally there?
   - **Method:** For each of `opencode`, `junie`, `kilo`: run `<binary> --help` for a config-path override flag; if none is documented, try `HOME=/tmp/agent-skills-phase0/home <binary> --version` and `--help` and confirm (via `strace`/`dtruss`-equivalent or simply observing where it writes) it is reading/writing under the scratch home, not the real one.
   - **Expected evidence:** The command succeeds and any files it creates appear under the scratch home, confirmed by listing the scratch home before and after.
   - **Stop condition:** If an agent cannot be redirected away from the real `$HOME` at all (no flag, and the `HOME` override is ignored or partially honored), every behavior experiment for that agent is **Inconclusive by default** and must use the most conservative method available (read-only inspection of real config, or a throwaway macOS user account) — documented explicitly per experiment, not silently skipped.

# 4. Reporting

Every experiment's verdict (Confirmed / Contradicted / Inconclusive), method actually used, and evidence observed is recorded in `initial-environment-review.md` (per the guideline's §6.3), redacted per §4.5-equivalent rules, before Phase 1 begins. A **Contradicted** result on V1, V2, V5, V6, V14, or V15 specifically must stop and present its impact on the architecture before any further phase is approved, since the guideline's adapter designs (§5.6, §12, §13) depend directly on these.

V21 and V22 are internal to the manager rather than to any external agent, so they are listed here for completeness and traceability but are actually executed once the relevant module exists (early Phase 3/Phase 9), not strictly before Phase 1 — this is noted so their absence from the initial Phase 0 report is not mistaken for an oversight.
